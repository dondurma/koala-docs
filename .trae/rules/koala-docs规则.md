# koala-docs 在线文档规则

> 创建时间：2026-10-03（只读，不随文档更新变动）

本规则约束 `koala-docs` 仓库内所有在线文档的新增与修改。这些文档通过 GitHub + Cloudflare 部署为在线站点，App 内部分页面以 WebView 加载，改动会直接影响线上，必须遵守本规则。

---

## 1. 语言与母版（最高优先级）

### 1.1 五种语言目录

| 语言 | 目录 | 说明 |
|---|---|---|
| 简体中文 | `docs/v1/zh/` | **母版，唯一内容源头** |
| 繁体中文 | `docs/v1/zh-HK/` | HK / TW 统一用此目录 |
| 英文 | `docs/v1/en/` | |
| 日文 | `docs/v1/ja/` | |
| 韩文 | `docs/v1/ko/` | |

### 1.2 强制的改动顺序

1. **先改母版 `zh`**：所有内容的新增、修改、删除，一律先在简体中文版落地。
2. **再翻译其余 4 语言**：以母版改动后的最终内容为唯一依据，逐语言同步 `zh-HK`、`en`、`ja`、`ko`。

禁止事项：

- 禁止只改母版而不改译文，或只改译文而不改母版。
- 禁止先改非母版语言再回填母版。
- 禁止在四语言版本里"顺手"加入母版没有的内容（内容必须严格对等，不做擅自增删）。

### 1.3 全语言对齐要求

母版的每一处改动都必须在 4 个译文里一一落地。以下内容必须逐项对齐：

- 一级标题、章节标题层级（`#`/`##`/`###`）与顺序
- 列表项的条数与顺序、表格行数与列数
- 提示块（`> ⚠️` / `> 📝` / `> 💡` / `> ✅`）的位置与语义
- FAQ 问答数量与编号（Q1、Q2……）
- 代码块（如 CSV 表头，须按该语言本地化，行数与列顺序一致）
- 图片引用位置与数量
- 文内相对链接（`./xx`）、锚点
- 页尾「最后更新」行

若发现某语言此前就缺失对应文档（存量缺失），本次改动触及该主题时必须补齐该语言文件，不得跳过；并在交付说明中列出补齐项。

## 2. 目录与文件命名

- 统一结构：`docs/v1/<lang>/` 下固定 `faq/`、`guide/`、`help/`、`legal/` 四个子目录，外加 `index.md`；`guide/` 下另有 `images/`。
- **文件名在五种语言中完全一致**（如 `01-template-bill-import-guide.md`），只有正文内容不同。禁止给不同语言起不同文件名。
- 文件名使用小写英文 + 连字符，沿用现有编号习惯；`guide/` 下按 `01`–`19` 顺序追加新编号，不插空、不重排存量编号。
- 在线文档页面不使用 frontmatter，文档标题用一级标题 `#`；本规则文件自身位于 `.trae/rules/`，按规则约定使用 frontmatter，不受此限。

---

## 3. 索引与导航同步

新增文档时，除正文外必须同步以下入口，且逐一对应：

- `docs/index.md`（站点根导航页，中文单份）
- `docs/v1/index.md`（v1 导航页，中文单份）
- `docs/v1/<lang>/index.md`（各语言落地页，含分区卡片）
- `docs/v1/<lang>/guide/index.md`（各语言用户指南列表）
- 新增语言或顶层栏目时，同步 `docs/.vitepress/config.mts` 的 `nav`。

链路与文案必须与正文标题一致；卡片标题、描述用该语言的本地化写法。

---

## 4. 翻译质量要求

- 翻译必须准确无误、符合当地语言习惯，禁止逐字直译导致语义偏差或生硬表达（尤其 `en`、`ja`、`ko`）。
- 禁止中英夹杂：除专有名词与产品名外，译文不得残留中文。
- 专有名词保留原文：微信 → `WeChat`、支付宝 → `Alipay`、貔貅 → `Pixiu`、iCost 保持 `iCost`。
- Apple 系统功能名一律使用该系统语言的官方译法，例如「轻点背面」：`en` = Back Tap、`ja` = 背面タップ、`ko` = 뒷면 탭。
- 标点与排版按当地习惯：中文用全角标点与「」，英文用半角标点与空格，日文用「」、韩文用「」/ “”。
- 术语必须全站唯一，同一概念在五种语言中只允许一种译法（见第 5 节）。发现同一名词存在多种译法时，按本规则统一，不得放任。
- **存量口径边界**：本规则只约束本次新增/改动的范围；存量文档中已存在的多种译法不自动批量回改，如需统一另立任务，避免一次改动牵连大量无关文件。

### 4.1 页尾「最后更新」格式（`guide` / `faq` / `help` 类，置于文末）

| 语言 | 写法 |
|---|---|
| zh | `**最后更新**：YYYY年M月` |
| zh-HK | `**最後更新**：YYYY 年 M 月` |
| en | `**Last updated**: Month YYYY` |
| ja | `**最終更新**：YYYY年M月` |
| ko | `**마지막 업데이트**: YYYY년 M월` |

### 4.2 法律条款类日期行（`legal/`，置于文首）

| 语言 | 写法 |
|---|---|
| zh | `更新日期：YYYY 年 MM 月 DD 日` |
| zh-HK | `更新日期：YYYY 年 MM 月 DD 日` |
| en | `Last updated: Month D, YYYY` |
| ja | 不写日期行（保持现状，不新增） |
| ko | `최종 업데이트: YYYY년 M월 D일` |

> 存量说明：ja 的 `guide/` 页尾现存带空格（`2026 年 9 月`）与无空格（`2026年9月`）两种写法，zh 的 `legal/` 日期行也存在带/不带空格两种；新增与改动一律按 §4.1 / §4.2 的写法，存量可择机单独统一，不强制随本次回改（见 §4 存量口径边界）。

## 6. 图片资源

- 存放于各语言自己的、**该内容所属模块下的** `images/`（如 `guide/images/`、`help/images/`），不合用同一张中文截图。
- 命名规则：`zh` 用中文描述（如 `1-辅助功能.png`）；其余语言用语言后缀（`1-en.png` / `1-ja.png` / `1-ko.png` / `1-hk.png`）。
- 图注（alt）用该语言书写，**只写图注本身，不要写尺寸**。
- **尺寸语法（实际行为，2026-10-03 实测）**：`![图注|350](./images/xxx.png)` 中的 `|350` **不会被 VitePress 解析为宽度**，而是整段并入 `alt`（产物为 `<img alt="图注|350">`），即**尺寸设置不生效、图片按原图尺寸显示**。存量图片（`guide/images/` 历史图与下载页二维码）仍带 `|NNN`，属已知存量、不强制本次清理；**新增图片请勿再写 `|NNN`**；确需限宽时改用 `<img src="./images/xxx.png" width="350">`。
- 只更新母版时，须同步补齐/替换其余 4 语言对应图片；含界面文字的截图须提供该语言的本地化截图。

## 7. 交付前自检清单

每次改动完成后逐项核对：

- [ ] 母版 `zh` 已先改，其余 4 语言已按其最终内容同步
- [ ] 五种语言文件均存在、均为最新，标题/章节/列表/表格/提示块/FAQ/代码块/链接/图片全部一一对应
- [ ] 非中文版本无残留中文（专有名词除外）
- [ ] 全文术语命中 §5 对照表，无同义词分叉
- [ ] 「最后更新」页尾行与 legal 日期行按对应语言写法落地
- [ ] `docs/index.md`、`docs/v1/index.md` 及各语言 `index.md`、`guide/index.md` 已同步
- [ ] 新增文档编号连续、文件名五语言一致
- [ ] 只核对本次改动范围，不因本规则回改存量文档的既有译法

最小对拍手段（各语言 guide 文件数应一致）：

```bash
for l in zh zh-HK en ja ko; do printf '%s: ' "$l"; ls "docs/v1/$l/guide" | grep -c '\.md$'; done
```

## 8. Git 提交

AI 只负责文件内容的新增与修改，**不执行 `git add` / `git commit` / `git push`**。提交由用户自行完成。改动完成后向用户说明改动了哪些文件、涉及哪些语言即可。
